# 小白外形与动画改进研究

研究日期：2026-11-21（Asia/Shanghai）。

本文保留改造前的研究基线与参数；第一轮实施结果和观看入口见 [造型与动作小样](visual-study.md)。

本次分三个方向并行研究：西高地犬种特征、动画表演与风格、当前 WPF 技术路线。结合当前源码重新编译并运行了现有离屏渲染工具，观察正面、侧面和三分之四视角。以下明确区分当前观察、外部资料与实施建议。

## 结论

建议采用“保留西高地的真实结构，使用动画角色的表情和表演”的路线。先改善脸部比例、眼睑、毛束组织和动作承重，再决定是否引入 Blender 或更换渲染器。

最值得解决的现状是：眼白和圆眼轮廓太突出、下半脸与颈部偏纵长、全身毛丝过细且层次相近、动作由较多固定时间循环驱动。单纯增加毛发或扩大眼睛，预计无法解决这些问题。这是基于当前渲染和源码的美术判断，不是用户偏好测试结果。

## 两种目标的区别

| 项目 | 更接近真实西高地 | 更接近动画电影角色 |
| --- | --- | --- |
| 轮廓 | 紧凑身体、明确犬类肩胸和后腿结构 | 保留犬种轮廓，适当强化头脸和爪子的形状 |
| 眼睛 | 深色、较少常态露白、眼睑包住眼球 | 可稍大，但通过眼睑和眼眶保持结构 |
| 表情 | 克制，默认放松，靠视线、耳位、口鼻变化表达 | 表情更清楚，眼睑、嘴角、耳朵和头姿协同 |
| 毛发 | 分区长短、硬直外毛与底毛的层次 | 先设计可读的大毛束，细丝用于边缘点缀 |
| 动作 | 接地、重量、关节与运动速度一致 | 同样可信，额外强调准备、停顿、接触和余韵 |
| 技术要求 | 若追求近景毛发与真实光照，资产和渲染要求提高 | 当前 WPF 可先验证造型与表演的改进 |

上表是本项目的设计方向建议；“动画化”不等于进一步增大眼白，也不要求将所有动作夸张化。

## 当前模型最值得改的五件事

### 1. 先改脸型和眼睛

当前新渲染中，圆形眼白边缘明显，下半脸较长，水平笑口持续可见，整体容易让人联想到人脸玩偶。

源码线索：`WestieModel.cs` 的眼白半宽为 `.093`，虹膜半宽为 `.057`；眼部调用 `EyeSurface` 时没有启用已有的杏仁形参数。`SculptedCoat.Field` 的头基础椭球纵向半径 `.400`、横向 `.318`，并继续叠加口吻和下颌体积。单个参数不能代表最终比例，但能帮助定位修改位置。

建议先去除细毛，做两套基础造型：一套更自然，一套偏动画。重点让脸框更圆、眼眶与额头连续、下颌更紧凑；侧面仍保留结实口吻，不能只把鼻子缩进脸里。默认嘴巴放松闭合，开心时再让嘴角、下颌、眼睑和耳位一起变化。

犬种依据：AKC 标准描述圆形脸框、中等深色杏仁形眼、结实口吻和小型直立尖耳。[S1] 标准用来保留辨识特征，不把展赛修剪当作唯一可爱的外观。

### 2. 毛发改为三层组织

当前 `GrowCoat` 进行 6,500 次毛束采样尝试，部分眼口等区域会跳过；身体与头部基础毛长分别为 `.104` 和 `.105`。已有局部长度与梳向变化，但新渲染中仍首先看到大量细白线。

建议按“底层体积 → 大中毛束 → 少量轮廓飞毛”组织：面颊向外展开、额头顺势分流、背部顺身体、胸口和胡须适度下垂、耳朵与腿部更短。先设计面颊、胡须、胸口等可识别块面，再决定细毛密度。

西高地有硬直外毛与短软底毛，头毛形成圆形面框，部位之间的毛型并不相同。[S1] 所以改毛流、长短和轮廓，比全身均匀加毛更符合本项目的目标。

### 3. 修正侧面的承重结构

当前侧面中，颈部较修长直立，后腿接近直柱，脚掌有圆盘感。后腿源码也主要由近竖直的椭球组合构成。

建议明确肩胸、上大腿、膝关节和后方飞节的关系；爪子保持厚实，使用少量趾块塑形。耳朵已做过缩短和埋入耳根的处理，优先级应低于眼睛、脸型和后腿。

### 4. 把循环摆动组织成行为

当前已经有视线跟随、转头缓动、嗅闻、双眨、耳朵抽动和摇尾。主要问题是许多动作由固定全局周期驱动：视线目标约 2.6 秒一段，眨眼按 5.3 秒循环，耳抽动按 9.3 秒循环；四腿主要以腿根单轴正弦摆动。

建议改成带停顿的短动作段：

- 待机：安静观察 → 发现目标 → 眼睛先看 → 头与耳朵跟随 → 保持 → 放松。
- 摸摸：察觉接触 → 主动贴近 → 眯眼蹭头 → 动作减弱 → 恢复。
- 喂食：看见 → 闻一闻 → 咬住 → 咀嚼 → 吞咽或舔嘴 → 满足停顿。
- 玩球：看球 → 转移重心 → 抬爪 → 明确触球 → 球开始运动 → 头部追踪 → 爪落地。

等待时长可在合理范围内变化，但不要改成每帧随机抖动。走路要区分支撑期和摆动期，并让步频、步幅与桌面位移匹配。源码结构存在滑步风险，本次没有量化实际滑步。

Disney 官方动画流程强调节奏、预备动作、跟随、次要动作及重量感；Pixar 合作科普介绍先设计关键姿态、再用曲线连接以传达情绪。[S2][S3] 这些支持优先设计动作意图和关键姿态。

### 5. 给光照和毛束留出层次

当前使用环境光加三盏方向光，毛发以纯色漫反射材质为主。新渲染中的白色细毛较亮，体块主要依靠冷色暗部区分。

建议先做柔和主光、适度补光的对照图，保留眼窝、下颌、胸腹和腿间的形体层次；避免整只狗均匀发白。可以评估简化的脚底接触阴影，但不要让阴影跟随整个窗口漂浮。

少量面颊、耳缘与胸前毛束可加入克制的延迟和阻尼，不必一开始做全身毛发物理。Pixar 合作资料强调毛发响应身体运动，以及可信度、美术需求和计算时间的平衡。[S4]

## 技术路线比较

| 路线 | 适用场景 | 对现有项目的影响 | 代价与限制 |
| --- | --- | --- | --- |
| A. 保留 WPF 程序模型 | 先改善造型、表情、动作和桌面观感 | 沿用现有窗口与互动架构 | 原生材质和当前 CPU 变形方式限制进一步堆细节 |
| B. Blender 制作并渲染透明动画帧，WPF 播放 | 固定或有限视角，优先画面完成度 | 可以保留窗口壳，替换宠物显示部分 | 视角、表情和动作需要预制；素材与解码内存随组合数增加 |
| C. Blender 角色资产加现代实时渲染器 | 自由转头、动态视线、高质量材质与骨骼动画 | 建立资产、动画和渲染管线，迁移范围最大 | 透明窗口、鼠标穿透、托盘和多屏要重新验证；不能预先认定更省资源 |

建议先走 A 做小样。如果固定视角也能满足互动需求，而 B 的同尺寸小样有明显优势，再考虑 B。只有明确需要自由视角和更丰富的实时效果时，才投入 C。

Blender 支持透明背景和独立动画帧输出，可以作为 B 的制作基础。[S6][S7] glTF 可承载骨骼变换和表情形变动画，但这不等于导入文件即可完整复刻 Blender 的毛发、材质和模拟效果。[S8] 当前程序也没有现成的 glTF 加载或标准骨骼动画播放管线。

微软明确提醒，WPF 逐帧修改网格顶点不一定高效，应控制动态网格规模、复用和冻结静态资源。[S5] 本项目应先测量整帧、分配与输入响应，再决定提高更新频率或重写渲染层。

## 建议的第一轮交付与验收

1. 同一机位制作自然版与动画版基础造型，各看正面、侧面、三分之四视角；先定脸和轮廓。
2. 为选定造型加入分区毛束和柔和灯光；缩到实际桌宠尺寸检查。
3. 制作一段 5–8 秒待机、一段完整拨球，以及一个完整走路循环；把关键接触事件放到同一时间轴。
4. 关闭爱心、星星、气泡后，仍能辨认好奇、享受和准备行动；确认脚掌接地、嘴与食物接触、爪与球接触、毛发不明显穿插。
5. 对比更新开销、内存和输入响应；实际修改应用后，遵照 AGENTS.md 执行完整检查、`build.ps1` 与便携包一致性验证。
